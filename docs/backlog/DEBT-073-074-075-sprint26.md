## DEBT-Q-073 — Refactor 409 handling (clean)

**Origen:** DR-S26-007 (B.4 quick patch)
**Sprint destino:** 27
**Prioridad:** Media
**Owner técnico:** Frontend Developer
**Estimación:** 1-2 días

### Scope

El quick patch B.4 introdujo retry condicional en `savings.service.ts contribute()` y mensaje UX inline en `contribution-modal.component.ts mapErrorToMessage()`. Refactor proper requiere:

1. **Jitter en backoff**: actualmente 500ms fijo. Añadir randomización ±100ms para evitar thundering herd si se amplía a más retries futuros.
2. **Logging observabilidad**: `console.warn('savings.contribute.retry', {goalId, attempt})` en el delay handler para correlación operacional.
3. **Cobertura ampliada**: aplicar el mismo patrón retry/UX a `closeGoal`, `configureAutoRule`, `pauseAutoRule` (también pueden colisionar bajo concurrencia teórica).
4. **Considerar interceptor global**: evaluar si vale la pena un `concurrency.interceptor.ts` global vs el patrón local actual. Pro global: DRY. Contra global: rompe consistencia con resto de manejo de errores inline en savings.

### Criterios de aceptación

- [ ] Jitter ±20% en backoff
- [ ] Logging visible en DevTools console
- [ ] 4 endpoints cubiertos (contribute, closeGoal, configureAutoRule, pauseAutoRule)
- [ ] Decision Record DR-S27-XXX documenta interceptor vs local
- [ ] Tests unitarios spec ng (cuando exista infra)

## DEBT-FE-074 — Refactor unificado auth

**Origen:** DR-S26-008 (Hallazgo 1 auth guard)
**Sprint destino:** 27
**Prioridad:** Alta (bloquea evolución cualquier feature con auth)
**Owner técnico:** Frontend Tech Lead
**Estimación:** 2-4 días

### Scope

Cierra DEBT-033 (refactor TokenService/SessionService abandonado) y unifica los 3 sistemas auth coexistentes:

| Sistema actual | Storage | Estado |
|----------------|---------|--------|
| Legacy LoginComponent | `localStorage.access_token` | Funcional |
| TokenService/SessionService (DEBT-033) | `sessionStorage.bp_access_token` | Sin escritor → inservible |
| TwoFactorStore (OTP US-002) | memoria | Interceptor orfano no registrado |

### Plan refactor

1. **UN storage canónico**: decidir `localStorage` vs `sessionStorage` con consideraciones seguridad (XSS, privacidad pestaña).
2. **UN writer**: `TokenService.setTokens()` debe ser el único punto. `LoginComponent` y OTP flow llaman a `tokenService`.
3. **UN interceptor**: registrar `authInterceptor` moderno (`HttpInterceptorFn`), eliminar `JwtInterceptor` legacy.
4. **UN guard pattern**: `AuthGuard` y `goalOwnerGuard` (y futuros) usan `SessionService.isAuthenticated()`.
5. **Token expiration handling**: chequeo `exp` JWT en cada request, refresh proactivo.
6. **Refresh token flow**: completar el ciclo refresh definido a medias en TokenService.
7. **Clear-on-logout**: borrar storage + memoria + cookies si las hay.
8. **Tests E2E UI-driven**: cobertura mínima de flujos navegacionales auth.

### Criterios de aceptación

- [ ] 1 solo storage en codebase (grep verificado)
- [ ] 1 solo writer (LoginComponent + OTP llaman a TokenService)
- [ ] 1 solo interceptor registrado en module
- [ ] 2 guards (AuthGuard, goalOwnerGuard) consistentes
- [ ] Test E2E UI: login → click meta → detalle abre OK
- [ ] Test E2E UI: login OTP → click meta → detalle abre OK
- [ ] Refresh token funcional con expiry < 5min
